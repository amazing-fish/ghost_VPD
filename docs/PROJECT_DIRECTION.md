## 目标与方向

项目的交付单位是可复测的 VPD 用例：从文字目标和当前设备事实出发，检索已有知识与能力，执行可验证的原子步骤，用独立且适用的产品判据判断结果，保留原始现场，再经人工确认沉淀为可复测资产。

目前的执行、判定和知识分层支撑这个方向。继续收敛 `Observer → Executor / Dispatcher → Verdict → Case` 现有链路；没有现行问题要求增加 Planner、EventBus、向量库或另一套 Verdict。框架测试证明模拟环境中的逻辑，不能计为正式产品覆盖。

## 本次漂移修正与仍存欠账

- 文档入口漂移：旧协作规范把 PR #2/#7 当作未合入；本次纠正主干入口事实，继续区分 Legacy 与 Skill。
- 知识成熟度漂移：旧 README 声称知识全未确认；本次替换为固定时点统计，入口选择仍不等于产品判据确认。
- 取证方向漂移：#32 已取代 #9 的脱敏治理项，#16 的豁免开关方案已否决。PR #38 已删除整条隐私确认与运行级脱敏链路，统一原文取证，不再新设豁免开关。
- 证据时效漂移：旧空树诊断会缓存覆盖物；PR #38 已改为每次采集当前整屏树，避免窗口变化后引用旧诊断。
- 判定证据漂移：旧最终断言重新从磁盘装载 stale 树，会把已失效观测恢复为可判定；监视窗口也可能把过时采样中的“未看到”当作“不存在”。PR #38 已封闭加载与判定入口；有效正面采样继续支持已见事实，过时采样留下不可判定缺口。
- 资产确认缺口：主干原来仅在 regression 终态强制 reviewer。本变更为 #30 增加独立 asset_review，探索资产晋级任一级及 suite/经验验证的全部批量入口先审核；单条诊断保持 informal。来源联合识别，审核绑定可执行内容、审阅语义和执行上下文，不重写既有重放指纹。已随 PR #40 合入，当前 5 条探索资产没有替人补审核。
- 测试仍依赖生产数据：`tests/conftest.py` 复制 data，再调整确认状态与 scope。#9 后续应分离稳定测试契约与可变知识数据。
- 版本边界：既有 replay dependency_hash 仍覆盖目标、状态、流程和判据；#30 新增审核绑定 policy、全部 vpdtest 引擎文件、APP/布局/弹窗/模板，并检查每次批量调用。正常生命周期与有效知识确认不使审核失效。policy/layout/dialogs 共用本次快照；源码与模板运行中并未加锁，需保持不变。本地 reviewer 声明不等于身份认证。

取证可用、业务证据可判定、动作可下发需要分别成立。#32 保留截图 APP 白名单；白名单内 APP 切换可留截图，但旧业务树为 stale，不能拿它定位或制造后置通过。整屏诊断树用于解释覆盖物与已登记弹窗，不替代目标 APP 的业务树。动作授权、锁屏检查、触摸归属、安全暂停和运动看门狗继续在现有执行关口生效。外置密钥引用及生成资产的参数分类继续存在，现场树、错误、事件不动态替换。
