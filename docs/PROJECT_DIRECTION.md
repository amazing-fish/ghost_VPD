## 前置、选支与产品结果

[#56](https://github.com/amazing-fish/ghost_VPD/issues/56) 承载最小分支判定契约。先依据当前、有效、独立于被测结果的前置证据选择分支，再应用该分支的产品断言：

| 前置证据 | 处理 | 汇报与覆盖 |
| --- | --- | --- |
| 明确满足 | 执行适用分支 | 适用且已确认的判据 + 有效结果证据得出 pass/fail |
| 明确不满足 | 该分支不涉及（not_applicable） | 不计失败，不冒充通过，不计覆盖 |
| 缺失、过期、矛盾 | 适用性未知 | 继续取证或保留未知，不能跳过制造通过 |
| 明确采集/执行异常 | error + tool/environment 归因与阶段 | 保留产品结论及原始错误；不计覆盖 |
| 策略拒绝、预算耗尽、外部输入交接 | blocked | 正常受阻不机械改为 error |

所有分支都不适用不能聚合为 passed。故障专用场景在独立证据明确不满足时不涉及；通用算路只有事先定义健康/故障契约，才能按实际分支评价。不能因为算路成功或开始 enabled，再反推健康并改选可通过的分支。guard 须关联 obs、时间与作用范围，避免旧声明无限沿用。

## 本轮动作契约与知识修订

首包只修“接受参数但未兑现”这一可靠性缺陷。当前 `act swipe` 是容器滚动，不支持指定起点与自定义时长；错误参数在动作前明确拒绝，历史请求不能静默固化为普通滚动。操作结果 passed 仍只按已声明的后置条件解释，不表示 AVM 视角或地图效果已验证。

完整手势支持还需处理窗口身份、实际起止点、触摸归属/副作用、水平回放与固化语义。设备 `uitest uiInput swipe` 的末参数是速度 **px/s**，不是毫秒，见 [OpenHarmony 官方参数表](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/application-test/uitest-guidelines.md)。#52 中“2000ms 慢拖/600ms 快扫”的推断先纠正，保留原始命令、参数原值与观察，待执行机版本/帮助与实际时长对照后重建结论。

raw HDC/uitest 仅保留为历史人工/探测来源，不能写成绕过 Dispatcher 的默认自动化替代。截图字节变化只说明画面变化，不独立证明视角身份、七档遍历或循环。知识入库保留观察、操作经验与待验证产品契约的区别。

执行与证据纪律的唯一完整说明见 [ISSUE_COLLABORATION.md](ISSUE_COLLABORATION.md)；动作契约见 [contracts.md](../vpd_skill/references/contracts.md)。
