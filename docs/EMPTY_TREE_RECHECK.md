# 暂态空树复核边界（Issue #221）

后置检查使用原 `timeout_s` / policy 上限计算出的 monotonic deadline，不新增预算。
当目标 APP 在前台但 bundle 树为空，且该 deadline 尚未到达时，在整屏覆盖诊断之前最多重读一次 bundle 树；重读前后都检查前台。初始树和重读树保存在不同证据文件，`tree_recheck` 记录关联。未提供 deadline 的普通观察保持原行为。

- 只读重采不是动作重试：不会重新 launch/tap/input，也不改变未知动作接管或车辆权限。
- 重读中前台变化，即使随后切回，也不使用该树；错误和持续空树保持原错误/未知结论。
- 同一 post 的 fresh 观测已经成功整屏诊断、无执行错误且未命中登记弹窗时，恢复只引用该诊断，不重复整屏读取。不把 no_cover 当作业务状态成功。
- 命中弹窗仍走原能力与动作前复核，不复用旧坐标。
- deadline 只控制是否发起新增纯读取，不中断已执行的 HDC 命令。因此单次 dump 本身过慢仍可超出窗口。没有自动加时、没有保证实机暂态空树一定消失。
- 不改历史运行或既有接管标记。真实设备需要另轮独立验收；离线测试不是产品通过证据。

现场触发：`run-20261111-233317-e244` 的首轮后置观察 25.81s / timeout 15s；obs-0007 bundle 空根但截图可读，恢复再次 no_cover。obs-0004 前台变化原因未知，不归因用户或 APP。不能从此单例确定空树根因。

验证：`python -m pytest tests/test_empty_tree_recheck.py -q`（在 `vpd_skill` 下），包含假时钟、持续空树、前台变化、采集失败和一发不重发。

## 保存后消费契约（P1 修正）

初版遗漏了落盘后消费者：在线检查使用重读树，但 `load_observation`、会话固化和离线 scope 诊断仍读初始 `tree.json`。此前本地审查未覆盖这条生产链，不能把在线检查成功视为断言通过。

现在三个消费入口共用选中路径规则，只允许规范 obs ID 下的 `tree.json` 或 `tree_recheck.json`；路径缺省仅兼容旧记录，显式非法、缺失、跨 obs、链接/重解析点不能退回初始树。初始原件不删除。runner 的保存→重载→断言、带 at 的条件 guard、session 选择器/容器固化，以及 scope 诊断的读取/哈希均增加回归。
