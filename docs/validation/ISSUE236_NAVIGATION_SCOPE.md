# #236 导航定位收敛与资产影响

## 修复与边界

`tab_my` / `tab_car` 不再用无范围的同名文本或 XPath 定位，优先在 `TabBar` 内查找；只有已知窄屏可尝试底部 85%–100% 区域。其他四个导航目标本就限定 `TabBar`，一并加入回归。

这避免「我的」标题与导航同名造成假适配经验，或只有标题时被误当导航进而形成产品失败。选中态仍按现有规则读取可点击祖先，不修改 K-MOT 判据或 expected。

宽屏测试是合成侧栏树，不是真机验收。宽屏未暴露 `TabBar` 时明确未找到，不使用窄屏坐标猜测。普通 `tap` 仍会点击已选中的导航；仅 `ensure_state` 已有到达目标状态后不再导航的语义。本次不实现通用选中短路，不能据此关闭 #236 全部验收项。

## 已有资产的诚实迁移

逐一比较基线 `73baf23` 与新定义的 `dependency_hash`，变化恰为以下六个 motor_hm 资产：

- `TC-HM-S01`、`TC-MOTOR-HM-002`：状态仍为 regression，但历史审核绑定现为 **stale**，不再代表当前定义已获审核。
- `TC-MOTOR-HM-001`、`TC-MOTOR-HM-003`：draft。
- `TC-MOTOR-HM-004`、`TC-MOTOR-HM-008`：exploration_record。

未改任何资产状态、历史审核哈希、回放记录或判据，也没有批量重签。两份 regression 资产的历史证据仍可跨机器读取，但不是新定位定义的通过证据。重新运行当前定义、形成新的独立审核依据后才可恢复有效批准；实机验收仍须工作机完成。

`test_published_regression_assets.py` 原有「当前仍有效」断言因此出现 4 失败。本次将测试改为验证历史原值未改、当前 stale、旧重放不能证明新依赖，明确披露契约变化而非把旧批准重签成绿灯。

### 已暴露的既有审核契约差异

`require_review()` 仅在 `review_status.required` 为真且 `valid` 为假时拒绝。探索来源的 S01 被阻止；002 无探索来源，`preflight_batch` 与 `require_asset_review=True` 返回 stale/invalid 但仍允许执行。这个既有行为不等于 002 仍有有效批准；本次没有扩大到修改准入规则。若产品要求所有 regression 资产都强制有效审核，这需要单独修复并补批量入口测试，不能宣称当前所有 stale 资产均被强制阻止。

## 本地证据

- 新增合成树首轮：旧实现 16 失败 / 8 通过；修复后相同 24 项全过。
- 增加漂移回放用例：25 项全过，重名标题不再产出 locator_preference 候选。
- `test_experience.py` 生命周期测试在隔离工作区显式注入旧缺陷，不再要求生产保留坏定位。
- `test_layout.py` 保持窄屏/宽屏定位行为回归。
- 这是本地测试，不是新增实机通过证据。
