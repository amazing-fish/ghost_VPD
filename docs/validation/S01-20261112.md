## 换机复用：历史行为与新规则

本文最初只同步验证说明；后续已将完整 regression 定义、既有审核与历史同步入库，见[跨机同步记录](PORTABLE-REGRESSION-ASSETS-20261112.md)。不上传经验库或扩张权限。历史 regression 不等于另一台机器本次执行已经通过。

**验证当时的行为（基线 011ac8f）：** agent 审核有效性会重新读取本机原件。缺少原件曾使审核变为 stale / valid=false 并阻止批量准入。这是当时机制的记录，不是新的使用要求，也不应要求用户为同一定义重复签字。

**新规则随 [PR #229](https://github.com/amazing-fish/ghost_VPD/pull/229) 落地（依赖 [PR #227](https://github.com/amazing-fish/ghost_VPD/pull/227)）：** 本文不把待合入机制写成 011ac8f 已有行为。既有审核复用核查绑定、撤销状态、静态风险及审核记录完整性，不再以本机是否留存旧 run、树或截图决定审核有效性。readiness / promote 也移除旧引用目录存在性的重复门禁。原件缺失或改变本身不撤销既有审核，不阻止复用，不要求为此搬运原件、重复取证或再次请用户审批。

新规则中，`evidence_verification.status=not_checked`、`affects_review_validity=false` 明确表示复用检查没有验证本地原件。`case review-route` 仍可单独诊断原件；其 evidence_needed 不等于既有审核失效。签发新的 Agent 审核仍核验原件；同一 run 与既有证据 hash 不一致时不能冒充原证据重签。

跨机复用需要可用的资产定义、既有审核记录及匹配的执行依赖，而不是搬运旧原件。实际执行仍核当前设备、适用性、动作权限和结果；新运行不能继承历史 passed。若定义、依赖或静态条件改变，或审核被撤销，应按具体原因处理，不能只凭本文、reviewer 名称或历史成熟度绕过这些检查。旧原件继续本地保存供追溯，不改写旧 run，也未设计新的证据共享服务。
