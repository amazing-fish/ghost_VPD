## 本轮工程修复

发现 `run_case` 的环境准入原先只比较适配器业务事实与 `--env`，
`app_version`、`device_form` 的实测值到判据判断时才使用。
因此匹配的人工声明可以掩盖实际不匹配，并触发启动/解锁/弹窗关闭；
反过来，真实版本匹配但未重复填写 `--env` 也会阻塞。

现在准入与判据共用 `run_facts`：APP 身份、版本、设备形态取本次实测，
实测未知保持未知，声明不能替代。先检查用例环境，再允许自动解锁与已登记弹窗恢复；
解锁后重新测量并复核。缺失或不匹配按环境阻塞，保留具体 required/actual 与未执行步骤。
`layout_requirements` 也在恢复前与解锁后检查，独立的宽窄屏/方向/折叠条件不会等到动作后才阻塞。
账号、车辆、园区和任务等当前无法测量的条件仍须现场确认后声明。

回放里的 `1.0.26.100-replay` 不等于 `1.0.26.100`：
测试候选生产版本的合成场景必须显式模拟该版本，不用 `--env` 冒充设备版本。
这不改变生产资产、policy、产品知识状态、资产审核或动作授权要求。

Windows 全量运行还在固定主干复现了 JSON 原子替换的 `WinError 5`：
8 项测试在写入树、回放状态或知识文件时中断；环境门槛修复后、写入修复前的全量也有 7 项同类失败。
因此共用 `write_json` 仅对 Windows 5/32/33 的文件替换错误重试同一个临时文件，
最多 5 次、累计等待 0.5 秒；不改成截断写入，不重新下发设备动作。
持续拒绝或其他错误仍抛出原错误，旧文件不变，待写临时内容保留。
`exclusive=True` 原始证据仍使用独占创建，存在即拒绝覆盖，不走替换重试。
修复前的两份全量失败日志保留，不将它们改写成通过。
