# 解锁输入：已修复的边界与尚未提供的能力

## 现在能做什么

`HdcDevice._run` 启动的每个子进程都使用独立环境副本，去掉
`VPD_SECRET_LOCK_PIN` 与 `VPD_SECRET_LOCK_PIN_*`，键名不区分大小写。
设备发现、状态查询和指定设备命令都经过这里。PATH、HDC 设置与其他键保持原样，
父进程环境不被修改。新增测试只用合成值、替身 subprocess 和本地 Python 子进程，不启动 HDC。

这修复了一个不必要的暴露面：PIN 是宿主侧解锁逻辑的输入，HDC 不需要继承它。
既有用户自行配置和授权的解锁、防重入、逐位状态复核、预算及 safety hold 保持原样。
本修复不授权当前会话读取或使用任何 PIN，也不证明现场曾发生泄漏。

## 这不是一次性安全输入通道

当前 `unlock` 仍没有受信任的逐次确认输入组件。现有 env/config 是旧配置兼容，
不是在本次动作中获得的安全确认；不要据此新增、读取或传递真实 PIN。
不得让用户把真实 PIN 发进聊天、命令参数、脚本、日志、临时文件或环境设置命令。
没有符合当前授权和安全要求的输入路径时，请用户直接在手机上解锁，再只读核对状态。

现有实现还存在以下未被本修复解决的边界：

- 点击位置会进入 HDC 命令参数；固定键盘的有序坐标可以表达数字序列。
- 底层 `raw/error` 保留原文，不能保证命令或输入上下文不会被底层回显。
- guard 位于 workspace 的 runs 目录，仅共享同一路径时能跨进程互斥，不是跨 workspace
  的全局设备锁；直接
  `wake_unlock(pin)` 是兼容入口，不能当作统一的一次性凭证消费器。
- Python 字符串和环境/config 的源值没有物理零残留保证。

正常事件不带 PIN 文本或 coordinates 字段，只说明这些字段被省略。
不等于 argv、继承环境、异常、进程内存、系统转储和外部监控全都安全。
本切片只解决上述继承环境一项，不修改原始业务证据策略。

## 何时可以实现真实一次性输入

先证明平台能力，再新增最小接口，不先制造只在 Replay 里工作的“安全”协议。

1. **可信交互与逐次确认。** secret 直接进入受信任本地组件，模型、工具参数及普通
   终端不可见；确认明确本次设备、用途、一次尝试及风险。回调返回 true、masked input
   或 `getpass()` 本身不是可验证的授权凭证。
2. **绑定与独占。** 一次凭据绑定设备、任务及短有效期，原子消费；跨进程和跨 workspace
   同一设备不能同时输入。拒绝、过期、取消或失败都结束这次凭据，不能重放。
3. **可信注入。** 不通过 argv 或可回显的 shell 文本表达 secret 或其可还原序列；紧邻
   注入确认可信接收者，保留 Dispatcher 门禁。锁屏状态本身不证明当前点击接收者可信。
4. **失败与清理。** 可能已经输入时保留阻断，不自动补发、重试或清空。只输出固定安全
   状态；不输出 raw/error、坐标序列、异常 locals、截图或树中的输入。覆盖自有可变缓冲
   只能作有限承诺，不能声称解释器和操作系统中所有副本已擦除。

后续验证至少覆盖拒绝、过期、取消、双重消费、设备切换、跨 workspace 并发、首位前与
中途异常、未知回执，以及底层故意回显合成 secret 的情形。测试须同时检查输出、文件、
事件、命令参数和子进程环境。只有合成测试通过不能开启真实 PIN 通道；仍需平台实现的
独立安全评审与受控验收，不新增真实 secret 测试资产。
