# 资产偏差：AI 先判断，再安全续行并告知

本协议供加载本技能的宿主 AI 执行，复用 `observe`、`act` 和会话证据；不是执行器内的无人值守模型回调，
也不是新的安全豁免。执行器不从相似文字推断控件身份。测试数据、定位经验、产品判据是三件不同的事。

## 先判断是否允许继续

1. 保留原 run/步骤、首次异常、当前判断和证据引用。先读 `dispatched`、`effect_unknown`、
   `action_required`、安全暂停和动作预算。未知效果、接管标志、预算耗尽、安全暂停、危险动作、
   未授权数据修改：停止物理动作并告知测试人，不通过换 session 或更换选择器解除。
2. 可继续的失败例如可靠未下发的失效文字定位。立即 `observe` 获取新树和本地截图，
   对比既有目标的稳定 ID、控件类型、父容器、页面位置和原操作目的。ID 相同也不是跨页面身份保证。
   必须有唯一、完整可见的当前目标，实际接收者和副作用仍经执行器复核。只有文字近似、第一行、
   地址相同、相同坐标，或出现多个候选，都不够。若文字/路径本身是被测要求，不可把替代操作当成该要求通过。
3. 区分仍在加载与识别漂移。用 `act wait` 在既有超时上限内观察原后置，不重复已成功下发的导航。
   `qk_vpd_home` 原来已有轮询与 20 秒资产超时，不能由摘要里的「搜索」推出只须延时或弱化签名。
   比对原 attempt 的 `post.elapsed_s/timeout_s/polls`、`state_diagnostics` 与后续帧，确认原签名每个条件。
4. 若确认只是低风险导航控件改名，AI 在**同一 agent session** 使用稳定 ID + 父容器重新定位，
   并保留原独立后置要求。原来是 `run` 时，可另建有明确原 run/step 关联的诊断 session，
   但只允许先再观察。新 session **不继承**原 run 的动作计数/预算；只有核对完整 run、cleanup、会话累计动作及未解风险并证明仍在原授权和剩余预算内，才可决定是否物理续行。无法证明则停止动作并请测试人处理，不能以新预算绕过限制。操作必须调用既有 `vpdtest`。
   不修改正式 targets/states、不批准经验、不改 Oracle、不把 `expect` 降为 `@in_app` 来求通过。

## 可执行例子（占位符必须替换为本机独立观测，不直接照抄上机）

在原失败可靠未下发、无任何接管/未知效果，且父容器/稳定 ID/角色已独立核对后：

```powershell
.\vpdtest.ps1 observe --app <app> --device <device> --session <same-session> --label "原run/step的改名核对"
.\vpdtest.ps1 act tap --app <app> --device <device> --session <same-session> --select "id=<stable-id>" --within "id=<parent-id>" --expect <original-independent-state>
```

CLI 的现场选择器会重新定位、下发前复核，并通过现有 policy、前台、可见性、接收者与动作预算门禁。
AI 读取返回的 `result/diagnosis`，只在原独立后置确实满足时继续剩余低风险探索；失败则停止该分支。
步骤成功只证明这次动作，不能将原 run 改为通过。后续正式资产须走现有 from-session/lint/review/重放，
且候选不能自审自批。已有 locator preference/wait timeout 经验也不自动 adopt。

## 收藏是本轮数据，不是固定名称

收藏名称可以按本轮设置，不用把「1号车位」改成另一个永久常量。优先独立读取现成合适对象；
授权已覆盖且任务允许设置时才创建隔离的 run 唯一名，记录创建前状态、创建后的独立读回和对象身份，
结束只恢复本轮创建/修改的对象。未授权不能写收藏，读不到编号不能编造编号，不能从待测搜索结果反推输入真值。
名称查询、编号查询分开验收。输入可设置不等于产品规则已确认。

## 告知测试人，不把每次偏差都变成审批

- 能安全继续：在原任务会话告知「发现什么偏差、依据什么继续、原结果保持什么状态」，继续后补结果。
- 无法安全继续：立即告知唯一需要人做的事、当前停止点及风险，不重复尝试未知效果动作。
- 告知内容：设备/APP/用例/步骤、旧资产与现场的必要文字差异、判断依据、已做动作与结果、
  剩余缺口、原 run 与诊断 session 的本机证据引用。原始截图/树/日志留工作机，仅允许 Issue 必要文字交接。
- 同一偏差只发起一次通知，状态改变再更新。成功恢复和待人工接管分开写，不把产品结论写成恢复状态。
- WeLink 按 #254 复用外部项目的 bot 发送能力；收件范围、形式和持续授权未明确时不外发。
  本协议不新增发送实现，也不声称已投递；一般任务使用当前已授权任务会话；工作机任务只使用既有 Issue 必要文字，不另开消息会话、不外发原始证据。外部失败明确标记未送达。

## run 输出的宿主入口

`run` 的精简输出在最终顶层步骤可靠绑定到最后 attempt/obs、且仍为 `target_unresolved` 或
`postcondition_not_met` 时附 `host_followup`。宿主读 `steps[].step/attempt/final_obs` 和 `guide`，
按协议先检查完整记录。`next=observe_only` 仅表示下一步可考虑重新观察，**不授权任何物理动作**；
有接管/未知效果/安全暂停时为 `next=inspect, requires_human=true`，原接管信号优先。
复合步骤、最终恢复已执行/效果未知/带新观测、缺少绑定和已经通过的步骤不推断偏差；明确未执行且没有新 attempt/post 的恢复仍引用原末次尝试。没有该字段也不代表没有问题。
通知仍由宿主按上述目的地与权限办理，不由执行器发送，也不伪造已送达状态。

### 步骤都成功，断言仍有差异

整例为 `pending` 时，宿主还应读取 `host_followup.assertions[]`。它只指向适用、非建议的终帧文本断言，且断言证据与关联成功步骤的 `final_obs` 一致。`observation_mismatch` 表示该帧与声明不符，`scope_undetermined` 表示在指定范围内无法判定；两者均**不表示已判定测试数据错、产品错或 AI 已执行**。跳过、只因判据未确认但观测相符、以及缺失证据的断言不触发。终帧以外的断言不在此入口范围。

宿主自己读取这些帧和本轮独立来源，再判断是输入、范围、测试数据、产品行为还是证据不足。例如先核独立收藏详情与编号，再查本轮实际输入和同帧结果行；不得从结果反填参数、改写原 run 或自行确认判据。若 cleanup 已结束 APP，历史帧不等于当前现场。旧运行完成后不能恢复原步骤；仅在独立真值与新一轮授权条件均成立时另行运行。无独立真值就报告缺哪一项，不重复搜索。普通判据待确认不等于需要发送消息；实际告知只用已授权渠道并区分未尝试、提交成功与有回执，CLI 本身不投递。
