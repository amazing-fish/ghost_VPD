# 运行监控：当前刷新与历史记录

`vpdtest console --no-device` 只读已有 `runs/`，不连接设备，不发起用例。
有设备模式仍沿既有投屏与手动操作契约；监控页面不新增调度、授权或控车入口。

## 最近监控与全部历史

默认仍显示最近 40 条运行并自动刷新。要找更早的运行，切换到 **全部历史（手动刷新）**：
首次进入读取全部合格运行，之后只有明确点击刷新才重新读取，不把大档案放进自动轮询。
按运行 ID、用例 ID 或标题做字面、大小写无关搜索，并可筛选运行类型；筛选作用于本次读取的全部列表，
再按每批 40 条展示。匹配数、总数和“显示更多”不会把被隐藏的旧记录误作不存在。

历史视图标明读取时间，筛选、展开和查看详情不更新该时间。它不是原子快照：目录扫描期间其他进程仍可能追加、
修复或删除运行。显式刷新会整体替换列表，不把两次变化中的偏移页拼接；列表次序以日志更新时间、运行 ID 确定。
详情仍独立刷新并显示自己的最近读取时间；选中项不会因为筛选或模式切换而静默换成另一条运行。
失败时保留同一范围的上次成功内容与时间，从未成功时说明没有可用快照；切换后的晚响应不能覆盖新范围。

只读接口 `GET /api/runs` 或 `?scope=recent` 保持最近 40 条；显式 `?scope=all` 读取全部历史。
`scope` 的空值、未知值或重复值返回 JSON 400，原 Host/token 校验不变。
读取仍受浏览器 8 秒请求超时约束；大量或特别大的日志可能超时，不据离线小样本承诺真实档案性能。
扫描缓存最多保留最近读取的 256 份文件，淘汰只影响下次重读成本，不删除运行或证据。
历史超过缓存容量时，手动刷新可能重新扫描多数旧日志；优先保留最新运行，避免档案浏览长期挤占实时监控缓存。

## 阅读详情中的选支证据

所选详情在最近和历史模式下都继续每 3 秒读取。同一次选择收到相同内容时，保留原详情节点，
仍更新“最近读取”并解除读取失败警告；不通过停止请求或冻结旧数据保留阅读状态。
有新事件、条件或断言内容时，刷新内容，并分别保留“选支证据：操作条件”和“选支证据：断言前置”
当前的展开/收起选择，不互相影响。重复点击同一运行、切换最近/历史列表也不重置该选择。

切换到另一运行时清空旧详情及阅读状态，包括 A→B→A 返回；旧请求晚到不能把状态带回。
某类证据在成功响应中消失时，移除该区并忘记其展开状态，再出现时默认收起；首次出现的证据区同样收起。
例如可选的 `run.json` 不再存在时，只显示本次可读取的事件，不保留已经缺失的条件/断言内容。
请求失败、找不到运行或响应无效时则保留上次成功内容、展开状态和读取时间，标明历史快照；
随后恢复读取同一运行仍保留现有证据区的选择。这不改变原执行结论、运行背景或诊断含义。

## 如何读状态

- **最近读取**：浏览器最近一次成功读取该列表或详情的本地时间，包含日期。
- **日志文件更新**：服务端现有 `updated` 字段，即运行日志文件的更新时间。它不是浏览器刷新时间，也不是进程心跳。
- **未收到结束记录**：服务端未标记结束，不证明进程仍在执行；无结束事件协议的记录也可能保持此状态。
- **日志已过期 · 执行状态未知**：沿既有服务端 `stale` 判断（默认 120 秒），不把静默、中断或等待误判为产品失败。
- **已结束 · 历史记录**：只代表已有结束记录。`passed/failed/error/blocked/pending/not_applicable`、证据级别、资产审核等仍读取原运行记录，不据刷新状态推断或重写。

浏览器刷新失败，或超过 12 秒没有成功读取，会提示“历史快照，不代表当前状态”。
已成功读取的内容和时间继续保留；从未成功读取时明确“尚无可用快照”。恢复成功后解除刷新警告。
列表和所选详情各自记录读取状态；列表成功不替代详情成功。关闭/后台暂停后的页面恢复时会先重新检查快照新鲜度。

## 慢请求与切换

每类轮询同一时间最多一个有效请求。只读 GET 读取超过 8 秒即取消，包括已收到响应头但响应体未读完的情况。
定时刷新随后可继续，失败不永久卡住监控。切换到另一个运行时先清空旧详情、取消旧请求；旧请求晚到、失败或 A→B→A 重选都不能覆盖当前选择。
状态接口读取失败会暂停页面的手动操作入口，待状态读取恢复；不改设备侧动作检查。

## 验证边界

自动测试使用合成运行记录、延迟/失败请求和页面实际函数，验证刷新与选择一致性。
证据展开回归使用实际 HTTP 处理器生成的详情、页面点击处理器和 3 秒回调；DOM 模型只验证节点与展开状态，
不代表真实浏览器的键盘、焦点、滚动、视觉布局或无障碍验收。
离线通过不代表 NEXT 真机投屏性能、设备当前状态、产品行为或正式用例覆盖。
历史运行的 `validation_level`、`informal` 和 `asset_review` 保持运行时快照，不自动升级为当前审核状态。
只读刷新不重签资产。读取器与 Console 的 Python 源码升级也属于既有 `engine_hash` 输入，旧审核绑定可能失效，
须沿[审核工作流](workflows.md)重新核验；历史运行中保存的审核状态不因此被追改。

## 记录损坏与恢复

单次运行的事件文件缺失、读取失败、结构异常时，列表仍保留其他健康运行。
`run.json` 是可选的历史详情文件：未生成时保持既有事件展示；存在但读取失败或结构异常时明确告警。
该运行显示“记录异常 · 进度未知”，通过 `read_errors` 标明源文件、原因和异常行数（如适用），
`progress_reliable=false` 时不展示完成进度条。已成功解析的原记录结论可以保留，但没有被重新判定；
数据读取错误不会制造产品 `failed`、`passed` 或覆盖资格。

读取器不修改原文件。JSONL 先按原始 CR、LF 或 CRLF 字节划分记录，再解码 UTF-8；可混用终止符，
空行忽略。字符串中的 U+0085、U+2028、U+2029 保留原样，不作为记录分隔。
Console 的无终止符末行等待追加，即使当前内容恰好是完整 JSON，也暂不计数；无效的完整行会明确标记。
UTF-8 字符与 CRLF 可跨读取块或刷新追加，重复读取不会重复计数。

会话的只读恢复有不同的尾行约定：完整 JSON 缺末尾终止符仍可读取；未终止的非法 JSON 沿用有界截断标记。
UTF-8 仅在最终 EOF 确实缺少多字节序列后续字节时按截断处理，并丢弃整个物理尾记录，
已解码前缀只用于留证，不能被当作完成事件或步骤详情。其他 UTF-8 错误，以及已终止或中间记录损坏仍报错。
这只明确读证据的边界，不自动修复日志、不改变会话续写阻塞，也不证明设备动作已经发生或未发生。

每次轮询都读取全部已缓存的原始字节（包括未终止末行）并验证 SHA-256，不依赖时间戳变化才检查。
只有前缀一致才复用已解析进度、增量解析追加记录；文件标识改变、截断或前缀不一致时重建全部累计状态。
因此同 inode 的增长式覆盖、中部修改、等长且保留时间戳的稳定重写也不会静默沿用旧结论。

每次扫描预检并拒绝非普通文件，再打开文件，用同一描述符确认类型、身份和初始长度，只读取该长度内的字节。
路径预检不消除检查与打开间的竞态，不能当作抵抗特殊文件恶意替换的安全边界。
打开后用文件标识和大小核对路径仍指向该描述符；读取前后的描述符、路径各自比较身份、大小、mtime 和 ctime。
时间戳不跨 API 比较：Windows CPython 3.12 的路径 stat 将 ctime 设为创建时间，而描述符 fstat 返回变更时间，
同一稳定文件的两值也可能不同。不检查读操作可能改变的 atime；
发生可见变化、提前 EOF 或 I/O 失败时，本次沿既有读取异常路径返回“记录异常 · 进度未知”，不自动重试。
失败候选不覆盖上次已验证的内部缓存，下次稳定读取仍可验证前缀并增量恢复；不会拿旧缓存冒充本次成功。
持续写入的大文件可能连续多次显示未知，直到一次读取期间稳定。

这里仅 JSON 解析是增量的：每次扫描都有 O(N) 旧前缀读取与哈希开销，未变文件也一样；
单次详情请求只扫描事件文件一次，摘要、尾部和读取错误共用锁内保存的独立观察，
不受随后其他请求更新内部缓存影响。成功读取的 `updated` 来自该次扫描记录的日志时间；
日志缺失或读取失败时仍以可读的文件或目录时间兜底，不因此恢复进度可信性。
可选的 `run.json` 最多读取一次，摘要结论/运行背景和详情使用同一份结果；
未结束运行和非 run 类型仍可展示可选详情，不因此补造结束或升级摘要结论。
run 类型的诊断文件按需最多校验一次，报告只检查是否存在；读取失败按来源告警，不在同一响应里重试。
全部历史及多日志同时刷新成本仍更高。冷盘、网络盘和真实并发性能未作保证。
摘要只增加固定大小的缓存字段，校验使用有界分块，不保留整份文件或持久句柄；
原解析器的 pending 仍可能随超长未终止记录增长，本次不新增截断或限长语义。
列表与详情请求仍独立读取；这些检查不是文件系统事务，也不提供 events.jsonl、run.json 和诊断文件之间的原子快照。
检查间隙的竞态仍可能存在，响应不保证包含本次观察之后的追加或修复，后续刷新再读取新内容。
这不是原证据的真实性/篡改认证或进程心跳机制。
非标准 JSON 数值（NaN/Infinity）、不能转为 UTF-8 的字符串、无效条件/覆盖行也按坏记录隔离，
不把文件内容或底层系统错误直接插入页面。真实执行器的对象步骤计划和历史字符串计划均兼容。

## 捕获到的运行中断诊断

`run` 在成功独占新目录后遇到 `Exception` / `KeyboardInterrupt` 时，尽力写入独立的
`run_diagnostic.json`，包含运行标识、目录、已知边界阶段、适用步骤及异常类型。
这不是产品 verdict，也不伪造 `run_end`。库调用仍抛出原异常；CLI 保留原错误格式，
附加 `run_diagnostic`，工具异常退出 3，捕获取消退出 130。`persisted: false` 表示
诊断文件未成功持久化，CLI 中的目录定位仍可用。SIGKILL、stdout 不可写不保证有输出。
目录冲突与分配前校验失败不写诊断；恢复旧目录不取得新诊断所有权。

Console 只消费 schema 有效且与目录 run_id 匹配的运行诊断，显示“已捕获取消”或
“工具异常”。坏日志仍显示读取错误及不完整进度；缺失诊断不推断取消，损坏或错身份
诊断保持未知。若报告或结束事件写入前已保存 run.json，既有产品结论另列，不表示
执行正常结束，也不被重新判定。suite 中异常继续向调用方传播，定位指向失败的当前
子运行，不补造 suite 结束或恢复流程。

阶段是最后进入的已知边界，不是推测的内部根因。安全字段只复制直接可读状态的
布尔摘要，未初始化为 null；不会为诊断调用设备或会变更状态的检查。设备动作可能
早于 dispatch 日志及 motion armed 记录，因此 false、空日志和缺少 armed 都不能
证明未下发或现场安全。本功能不自动停止、清理、重试或恢复，也不保证物理停止。
