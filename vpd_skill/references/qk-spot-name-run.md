# 运行车位收藏名称子用例

`TC-QK-230-SPOT-NAME` 是独立 draft。它输入一个本轮名称，严格清理输入框，保留两份搜索结果观测；收藏身份由核验人对照独立来源判定。它没有路点步骤，不测试按编号搜索，也没有继承 TC-QK-230 的历史。[原需求](https://github.com/amazing-fish/ghost_VPD/issues/106#issuecomment-6431475672) · [名称搜索范围裁决](https://github.com/amazing-fish/ghost_VPD/issues/80#issuecomment-6381962059)

## 工作机执行

1. 在本轮账号、车辆、园区选择任一已有的收藏车位。打开左侧卡片同一 `GridItem` 中的 `⋮` 信息面板，先保存卡片和面板的会话、观测 ID、时间、完整名称、车位类型、楼层和区分字段，再返回 VPD 首页。宽屏已见的入口是与名称同属一张卡片的控件；现场用整窗树和截图确认归属，避免按旧坐标查找。面板独立识别不同车位可用不同字段，编号是可能的见证。可选标签按钮的文字本身不能证明标签已选中。[当前版本工作机实测](https://github.com/amazing-fish/ghost_VPD/issues/118#issuecomment-6976988165)
2. 有搜索前取得的名称即可运行。若只有首页名称线索，记录来源与缺项，照常采名称行，收藏身份待判；没有查询词时不从结果反填。用最新 PR 代码，在 `vpd_skill` 中将此次实际读到的名称传给标准入口。设备参数使用 `hdc list targets` 所示序列号。

```powershell
$deviceSerial = Read-Host '输入 hdc 设备序列号'
$spotName = Read-Host '输入本轮独立读回的完整车位名'
.\vpdtest.ps1 run TC-QK-230-SPOT-NAME --device "hdc:$deviceSerial" --data "fav_spot=$spotName"
```

3. 若首页准备步骤实际重新启动了 APP，先对照两侧账号、车辆和园区；上下文无法对应时保留身份待判。打开新 `runs/<run_id>/run.json`，按 `steps` 找到 S4 与 S5 各自的 `final_obs`，用各自的 `observation.json`、所指结果树和截图复核两次取样。CLI 摘要不含所有断言证据。两帧的实际查询、结果行标题、同行身份字段须一致；只有一帧符合、列表仍在刷新、键盘遮挡候选、缺截图或有同名实体时，写明待判原因。比对时检查完整结果列表的其他类型 POI、裁剪或嵌套行；与编号同文的标题、相邻卡片、输入框回显都不能代替编号字段。虚拟列表未呈现的对象不能据此宣称全局唯一。
4. 只提交文字 issue，按下表逐项填写。原树与原图留工作机。无需再向用户确认这个查询该不该搜。

| 需记录 | 内容 |
| --- | --- |
| 同轮来源 | 实际 PR SHA、设备形态、APP 版本、账号/车辆/园区是否一致、来源会话和卡片/面板 obs、采集时间、车位类型、名称、楼层、区分标识及其字段位置。 |
| 本次运行 | 新 run ID、两个结果 obs 及时间、实际输入、各帧完整标题及其同行字段、相邻/同名候选、画面是否稳定、清理结果。 |
| 独立审核 | 核验人、两侧相符或冲突的具体证据、人工结论（本轮命中 / 待判及原因）。有适用的独立产品要求且能归因时，才另记产品问题。 |

自动检查提供页面、输入与行的六条观测线索，核验人对照的是两侧原件。已校对的编号须属于同一行中的编号字段；若同一园区、同类型仍有多个候选，或来源晚于搜索、换车换园区、计时或原件无法对应，身份待判。行内可选文字裁剪会使严格行线索无法判断；可在原件上分别辨认标题与可见字段，不能把缺项记成字段必显缺陷。

必需的 `favorite-identity` 断言在正常取证后返回 `pending`。参数被记录为 `run_arguments / measured=false`，人工结论另附上述证据与 run ID，不能改写 run.json。截图采集报错、设备异常和动作阻塞保留其原归因。本 draft 不接受这类运行作为确定性晋级重放。后续若要形成可自动晋级的版本，需先在独立收藏源和结果行之间建立可验证的唯一身份绑定，再复审新定义并重新运行。[当前资产机制](asset-readiness.md) · [路点与字段要求](https://github.com/amazing-fish/ghost_VPD/issues/108)
