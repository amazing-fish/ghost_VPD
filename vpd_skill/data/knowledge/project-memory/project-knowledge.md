## 1. 车外语音对讲：冻结业务规则（用例集的验收锚点）

用户确认的字面规则（新写/改写用例必须可追溯到这些规则，不得凭 ad-hoc 观察）：

1. 车速<15 准入 / 通话中>20 挂断
2. 下电唤醒复用 VPD 上电链路
3. 挂断后 3-5min 自动下电
4. EPA 无对讲按钮 / EPD≈VPD 可对讲
5. 来电接听才挂断
6. 主驾落座即断开
7. 蓝牙优先默认路由
8. 静音新通话重置
9. 「车主来电」车外提示音

对讲 KPI 时延指标：**上电 3s / VPD 热启动+3s / 成功率 99%**。

> 已按本架构 schema 提炼为 items.json 的 K-IC-001~010（kind=product_rule/requirement，
> source=reviewer，unconfirmed 待评审）。

## 2. 用例工程约定

- **编号与级别**：模块内顺序编号 + L1/L2 级别；重构会重编号（54 例原表 → 合并为 20
  例 VPDIntercom101–120 → 重构为 001–025；R19 通话、R18 连接降 L2，连接与网络 113–116
  改 L2）。编号不是永久标识。
- **命名**：用例名**不带括号内容**（如 012【VPD过程】先VPD后通话）；标题用【模块】
  前缀；模块名只在组内首行显示。
- **粒度原则**：「整体把握用例分类与量，避免过多过细，相同操作尽量并入观察点」。
- **模块合并而非一对一**：UIUX交互（103+104+121）、车端上下电与外显（107+108+109）、
  压测指标（124+125）等；「VPD过程」模块含两 L1：012 先VPD后通话 / 026 先通话后VPD
  （均覆盖巡航过程+泊车过程）。
- **用例生成器** `gen_cases.py`：可重跑；107 例 = 56 原例重构 + 51 问题回归/新增
  （源自 165 个实测问题 + PPT 五批 TOP 问题清单）；10 模块连续编号校验通过。
  交付件 `车外语音对讲-用例重构与问题回归.xlsx`（2 sheet）。

## 4. 缺陷提报约定（VPD 域）

- **手机端缺陷的正确提交通道 = VPD 界面右上角「反馈」入口**（问题描述需 VIN），不是
  直接走 DTS 提单。
- 提单标题 tag 顺序：**【模块】+【偶现/必现】+【端】+问题描述**；问题概述开头即给
  复现步骤（受理人 10 秒内判断）；首次提单的预期结果必须以**产品实际应有逻辑**为准，
  不以测试时观察到的错误实现为准。
- 严重程度裁定（实测表）：影响核心功能/安全类=严重；绝大多数上报缺陷=一般；仅文案/
  体验问题（如时间格式、协议图）=轻微。车载 HMI 端=三端必查（手机必查鸿蒙+安卓，
  车机必查 HUD+中控）。
